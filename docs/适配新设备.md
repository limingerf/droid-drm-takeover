# 适配新设备

把本项目跑到一台**没适配过的**设备上。全程不改逻辑代码，只填一个数据文件。

预计：摸清拓扑 1 小时，跑通接管 2–4 小时，触摸/网络调优另计。

> ⚠️ **第一次上机前请读第 0 节。** 最坏情况是黑屏 + 只能长按电源强重启。
> 数据不会丢，但未保存的工作会丢。

---

## 0. 上机前

| 检查项 | 要求 |
|---|---|
| 电量 | > 50%（接管期间充电逻辑可能不工作） |
| 现场 | 有人在，能手长按电源键 |
| root | KernelSU 或 Magisk，`su -c id` 能出 `uid=0` |
| 控制通道 | **不要只依赖 WiFi**。用 `adb`（USB 或本机转发），因为接管会断 WiFi |
| 已知数据 | 你接受这台设备可能重启几次 |

逃生口，从强到弱：

1. **长按电源 10 秒** —— 硬重启，任何情况下都有效
2. `adb shell su -c 'sh <payload>/display/desk-stop.sh'` —— 原地回安卓（半死状态，见下）
3. `adb shell su -c 'reboot'` —— 直接重启

**永远不要用试跑模式之外的路径做第一次尝试。** 第一次请用 `display/drm-takeover.sh`（150 秒自动回滚）。

---

## 1. 收集设备事实

```sh
adb shell getprop ro.product.model        # 机型，如 OPD2511
adb shell getprop ro.product.device       # 设备代号，如 OP6546L1
adb shell getprop ro.board.platform       # 平台，如 pineapple
adb shell getprop ro.soc.model            # SoC，如 SM8650Q
adb shell getprop ro.build.version.release
adb shell uname -r
adb shell getenforce                      # SELinux 状态
adb shell su -c id                        # root 上下文（u:r:ksu:s0 = KernelSU）
```

把这些记下来 —— 它们会进 `core/device/<codename>.sh` 的文件头注释。

## 2. 让适配层认出这台设备

`core/lib/device.sh` 按这个顺序匹配：

1. 显式指定：`DRM_DEVICE=<codename>`
2. 读 `ro.product.device` / `ro.product.model` / `ro.board.platform` / `ro.soc.model`
3. 别名表（`drm_device_alias_file`）把同一台机器的多种写法归一到 codename
4. 都不中 → `core/device/generic.sh`

所以：

```sh
cp core/device/generic.sh core/device/<你的codename>.sh
```

然后在 `core/lib/device.sh` 的 `drm_device_alias_file()` 里加一行，把你的
`ro.product.device` 映射到 codename。

## 3. 抓 KMS 拓扑（最关键的一步）

```sh
adb push <payload> /data/local/drm-takeover
adb shell su -c 'sh /data/local/drm-takeover/display/drm-diag-once.sh'
```

输出在 `/data/local/drm-takeover/run/logs/drmdiag/`。要看的是：

```sh
# 面板 connector：谁 connected、有哪些 mode
cat run/logs/drmdiag/sysfs-topology.txt

# 全部对象（connector/crtc/plane）的 ID 与能力
cat run/logs/drmdiag/kmsdump.txt

# plane ↔ crtc 的 possible_crtcs 矩阵
cat run/logs/drmdiag/kmsmatrix.txt

# atomic 能力自检
cat run/logs/drmdiag/atomiccheck.txt
```

> **不要**依赖 `rawprobe` / `drmatomic` / `atombisect` 的输出。
> 它们的默认对象 ID 是 piano（小米平板 8 Pro）的
> （crtc 206 / conn 67 / plane 157,161），在别的设备上结果无意义。
> 需要时加 `DIAG_LEGACY_PROBES=1` 显式打开。

## 4. 填 `core/device/<codename>.sh`

### 4.1 必填（不填跑不起来）

| 变量 | 从哪来 | 说明 |
|---|---|---|
| `DEV_CODENAME` | 你自己定的 | 必须和文件名一致 |
| `DEV_MODEL` | `ro.product.model` | 只用于显示 |
| `DEV_PLATFORM` | `ro.board.platform` | 只用于显示 |
| `DEV_SF_SVC` | 通常是 `surfaceflinger` | |
| `DEV_COMPOSER_SVC` | 见下 | **最容易填错的一项** |
| `DEV_DRM_CARD` | 通常 `/dev/dri/card0` | |
| `DEV_DRM_MAJOR` / `DEV_DRM_MINOR` | `ls -l /dev/dri/card0` | 节点被厂商删了要靠它 `mknod` |
| `DEV_PANEL_W` / `DEV_PANEL_H` | `sysfs-topology.txt` 的 modes | |
| `DEV_TOUCH_NAME` | `getevent -pl` 里的设备名 | **不要用 `eventN` 编号**，每次 boot 都变 |

**怎么找 `DEV_COMPOSER_SVC`：**

```sh
adb shell su -c 'ls /proc/*/fd -l 2>/dev/null | grep card0'
```

看哪些进程持有 `card0`。持有者就是你要在接管前停掉的那个。高通常见是
`vendor.qti.hardware.display.composer`，但**必须自己确认**。

```sh
# 确认它是个 init 服务
adb shell getprop | grep -i composer
```

### 4.2 强建议填（不填会退化到运行时发现，可能不准）

| 变量 | 说明 |
|---|---|
| `DEV_BACKLIGHT` | `ls /sys/class/backlight/`。留空则 lib 运行时扫描；扫不到会退回写 DRM connector 的 `brightness` 属性 |
| `DEV_BRIGHTNESS` | 你的面板亮度范围里的中间值。参考：piano 用 2048，OPD2413 用 1024 |
| `DEV_DRM_DRIVER_ALIAS` | **填 `vmwgfx`**。KWin 的 Hardware 白名单只收 i915/amdgpu/nouveau/vmwgfx，`msm_drm` 会被过滤掉。vmwgfx 在 KWin 里没有特殊 quirk，是最安全的伪装 |
| `DEV_WIFI_IF` | `ip link` 看无线网卡名 |
| `DEV_ROUTE_TABLE` / `DEV_ROUTE_PREF` | 见第 6 节 |
| `DEV_WATCHDOG_DISARM` / `REARM` | 见第 5 节，**不填会有严重问题** |
| `DEV_KERNEL_DEBUG_OFF` / `ON` | 不关的话每次 atomic 打印几百行，帧率崩 |

### 4.3 容器

```sh
DEV_CONTAINER=drm
DEV_DS_BIN=/data/local/Droidspaces/bin/droidspaces
DEV_DS_CFG=/data/local/Droidspaces/Containers/<名字>/container.config
```

容器需要：

```
net_mode=host          # 共享 netns，否则拿不到安卓的网络栈
bind_mounts=/dev:/dev  # 必须。已知取舍：容器能看到全部设备节点
privileged=full
run_at_boot=0          # 由我们按需拉起
```

> **容器与安卓只有一个目录可靠共享**：容器 `/root` ↔ 安卓
> `/mnt/Droidspaces/<容器名>/root`。
> 容器里的 `/data/local/tmp` 是**另一个**目录（inode 都不同），别拿它当通道。

### 4.4 钩子

```sh
dev_pre_stop_fixes()       { :; }   # 在 framework 还活着时做的准备
dev_post_session_fixes()   { :; }   # 会话起来之后的收尾
```

典型用途：蓝牙复位、音量归零、pogo 键盘固件重载。
需要访问安卓侧的属性/服务就放 `dev_pre_stop_fixes`（那时 framework 还在）。

## 5. 解除安卓稳定性守护（不做的后果很严重）

接管后 SurfaceFlinger 停了约 120 秒，安卓 `system_server` 的 watchdog 线程会杀掉
`system_server`，init 随后级联 SIGKILL `wpa_supplicant` / `netd` / `zygote` ——
**WiFi 掉线且 UI 不可用，只能强重启。**

所以接管前必须解除武装。先看这台机器上有哪些：

```sh
adb shell settings list global | grep -iE 'watchdog|nativehang|hang'
adb shell getprop | grep -iE 'hang|watchdog'
```

然后填：

```sh
DEV_WATCHDOG_DISARM="settings put global watchdog_timeout 86400000; ..."
DEV_WATCHDOG_REARM="settings delete global watchdog_timeout; ..."
```

**`REARM` 必须真的能还原。** 参考仓库的一个真实缺陷就是回滚脚本不还原这些设置，
导致用户**永久失去看门狗**（跑过一次常驻接管后一直残留）。

AOSP 通用项 + 高通常见项的起点：

```sh
DEV_WATCHDOG_DISARM="settings put global watchdog_timeout 86400000; settings put global stay_on_while_plugged_in 7"
DEV_WATCHDOG_REARM="settings delete global watchdog_timeout; settings delete global stay_on_while_plugged_in"
```

不存在的设置写进去只会报 `not found`，无害。

## 6. 网络

接管后 `netd` 被停，安卓那套 per-interface 路由表 + fwmark 没人维护，
一路落到 `32000: from all unreachable`。现象很迷惑：**有 IP、能 ping 通网关、外网不通**。

对策是加一条独立路由表 + 一条 rule，优先级夹在 netd 的 31000 和 32000 之间：

```sh
DEV_ROUTE_TABLE=1042     # 随便挑一个没被占用的
DEV_ROUTE_PREF=31500     # 必须 > 31000 且 < 32000
```

先确认没冲突：

```sh
adb shell ip rule show
adb shell ip route show table all | grep -o 'table [0-9]*' | sort -u
```

### ⛔ 红线：永远不要 `ip link set <wifi> up`

接管后对无线网卡做 `up` 会触发：

```
cnss: Failed to start MHI err=-110
Recovery is already in progress → ASSERT 2436
```

→ **adbd 死掉 → 黑屏**，而且只能强重启。

网络接管是**纯尽力而为**的：关联失败、DHCP 失败、出口不通，都只打警告，
绝不回滚已经上屏的桌面。这是设计选择 —— 屏幕已经归 Linux 了，为了网络把桌面
搞崩是净损失。

## 7. 触摸

### 7.1 找节点

```sh
adb shell su -c 'getevent -pl 2>/dev/null | grep -A3 -iE "add device|name"'
```

填 `DEV_TOUCH_NAME`（**不是** `eventN`）。`core/lib/display.sh` 的
`drm_touch_find_event()` 会按名字在 `/proc/bus/input/devices` 里反查。

> ⚠️ **不要对触摸节点跑 `getevent` 旁听。** 多次实锤：这会在某些厂商设备上
> 触发安全联动直接断网。要验证触摸请用 `bin/touchtest`（走合成器打点日志）。

### 7.2 坐标系

如果触摸位置和手指对不上（旋转 90°、镜像、偏移），需要校准矩阵：

```sh
DEV_TOUCH_CALIB="0 1 0 -1 0 1 0 0 1"
```

这是 libinput 的 3×3 变换矩阵，语义是：

```
[ x' ]   [ a b c ] [ x ]
[ y' ] = [ d e f ] [ y ]
[ 1  ]   [ 0 0 1 ] [ 1 ]
```

参考机 OPD2413 用的 `0 1 0 -1 0 1 0 0 1` = 90° 旋转 + 垂直翻转。

**留空则不注入矩阵**，libinput 用驱动自带的值。第一次先留空跑通，再调。

调试手法：跑 `bin/touchtest`，屏幕上每个触点会画一个圆。
如果手指从左下角划到右上角、圆从左上角划到右下角，就是转了 90°。

### 7.3 合成器内注入（绕开 libinput）

容器里的触摸节点是我们自己 `mknod` 出来的，libinput 会因为缺少完整 udev 属性
而拒绝整台设备。要验证"合成器链路本身是好的，只是 libinput 不认设备"：

```sh
# 面板尺寸从 DRM 读，触摸量程从 EVIOCGABS 读，不再写死 piano 的 3200x2136
WAYLAND_DISPLAY=taketest bin/touchinj 30 /dev/input/eventN

# 坐标系不对时用环境变量调
TOUCHINJ_ROT=xyy WAYLAND_DISPLAY=taketest bin/touchinj 30
```

`TOUCHINJ_ROT` 四字符含义：`[面板X取自触摸 x|y][面板Y取自触摸 x|y][面板X翻转 f|n][面板Y翻转 f|n]`。

## 8. split 几何（双 DSI 面板）

很多平板的宽面板无法由单个 legacy pipe 驱动，必须用两个 plane 各推一半。
`kwinwrap` 需要在运行时知道：connector / crtc / 两个 plane / 每段宽高。

自动发现（推荐先试）：

```sh
bin/kwinwrap --probe-split
```

它会打印：

```
KWINWRAP_SPLIT_CONN=67
KWINWRAP_SPLIT_CRTC=200
KWINWRAP_SPLIT_W=1600
KWINWRAP_SPLIT_H=2000
KWINWRAP_SPLIT_PLANES=92,123
```

同时把发现过程（包括**候选 plane 列表**）写到 stderr。核对该列表，
如果选中的两个 plane 不对，就人工固定：

```sh
KWINWRAP_SPLIT_PLANES=<左>,<右> bin/kwinwrap --probe-split
```

> ⚠️ **PLANES 是唯一无法可靠自动发现的一项。** 需要两个"能驱动该 CRTC 且属于
> 同一 SSPP 组"的 plane，纯靠 `possible_crtcs` 枚举可能挑错。
> 自动发现失败时 `kwinwrap` 会**大声告警**，不会静默使用编译期兜底值
> （那是 piano 的常量，在别的设备上几乎肯定是错的，而且不报错 ——
> 现象是"kwin 起来了、也有 master、就是花屏"，极难定位）。

确认之后把结果写进设备文件或环境，`core/lib/display.sh` 的
`drm_kwinwrap_split_env()` 会在每次拉起 KWin 时注入。

## 9. 分步验证

**不要**直接常驻接管。按这个顺序，每步都确认了再往下：

```sh
# ① 环境体检（不碰任何东西）
sh core/switch.sh doctor

# ② 裸 KMS：能不能点亮面板
bin/drmatomic /dev/dri/card0 10

# ③ 试跑：进 Linux 150 秒后自动回滚
DRM_TRIAL_SECS=150 sh display/drm-takeover.sh

# ④ 触摸验证（在 ③ 的 150 秒窗口内，从另一个 adb 连接进去）
WAYLAND_DISPLAY=taketest bin/touchtest 30

# ⑤ 都通了才常驻
sh display/desk-takeover.sh
```

③ 成功但 ④ 失败 ⇒ 触摸问题，看第 7 节。
③ 就失败 ⇒ 看 `run/logs/` 下的 `kwinatomic.log` 和 journal。

## 10. 常见症状对照

| 症状 | 大概原因 | 看哪 |
|---|---|---|
| atomic commit 返 `-13 (EACCES)` | composer 还占着 master | `ls -l /proc/*/fd \| grep card0`；确认 `DEV_COMPOSER_SVC` 填对 |
| kwin 活着、有 master、屏幕花屏 | split 几何错 | `bin/kwinwrap --probe-split`，核对 plane |
| kwin 活着、面板有 mode、整屏纯黑 | `kactivitymanagerd` 没起来（plasmashell 会直接 `Aborting shell load`） | journal 里找 `Aborting shell load` |
| 面板有 mode 但完全没亮 | 背光被安卓关机流程写了 0 | `DEV_BACKLIGHT` / `DEV_BRIGHTNESS`；看 `keepbright.sh` 有没有在跑 |
| kwin 起不来，日志说找不到输出 | udev 记录没写对 / `DEV_DRM_DRIVER_ALIAS` 不是白名单里的 | `core/lib/display.sh` 的 `drm_write_udev_records` |
| 有 IP、ping 通网关、外网不通 | netd 的路由表没了 | 第 6 节 |
| 接管几分钟后 WiFi 掉、UI 崩 | watchdog 没解除武装 | 第 5 节 |
| X11 应用全部起不来、Wayland 全好 | KernelSU enhanced_security 杀了 Xwayland 的提权试探 | `DEV_NEEDS_KSU_XWL_SHIM=1` |
| `ip link set wlan0 up` 之后 adbd 死 | 踩了红线 | 只能强重启 |

## 11. 把你的适配贡献回来

```sh
git checkout -b device/<codename>
cp core/device/generic.sh core/device/<codename>.sh
# 填好，并在 core/lib/device.sh 的别名表里加映射
# 用 ✔实测 / ~推测 / ✗未知 标注每个值（见现有文件的约定）
```

**标注要诚实。** 把推测的值标成实测，下一个人会照着它调半天。
`core/device/opd2511.sh` 就是按这个约定写的，可以当模板。
