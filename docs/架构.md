# 架构

## 1. 两条独立的链

理解本项目只需要抓住一件事：**输出链和渲染链是分开的。**

```
输出链（谁把像素送上面板）
  KWin Wayland ──► /dev/dri/card0 (KMS, msm_drm)
                      ▲
                      └── 需要 DRM master

渲染链（谁把像素画出来）
  KWin Wayland ──► Mesa (Freedreno) ──► /dev/kgsl-3d0
```

接管做的全部事情就是**把输出链的 master 从安卓手里合法接过来**。
渲染链一个字都不改 —— 不需要 patch Mesa，不需要改内核，不需要自定义 GBM。

这也是为什么 wlroots 系合成器（sway / cage / labwc）在这条路上走不通：
它们依赖 `VK_EXT_physical_device_drm`，而 KGSL 不提供这个扩展。
KWin 不依赖它，所以是务实之选。

## 2. 状态机

重构前没有统一状态。参考实现只有一个 `takeover.ok` 空文件当标志，而
`drm-takeover.sh` 在结尾**无条件** `touch` 它（成功失败都 touch）——
判据从一开始就是失效的，两个守护进程的循环条件也跟着一起错。

现在只有一个状态文件（`$DRM_RUN_DIR/state`，`key=value` 格式，不是 JSON ——
安卓上没有 `jq`）：

| 阶段 | 含义 |
|---|---|
| `android-active` | 安卓在跑，我们没动 |
| `entering` | 正在进入 Linux（中途失败会回滚） |
| `linux-active` | KWin 持有面板 |
| `returning` | 正在返回安卓 |
| `error` | 上次失败了，`LAST_ERROR` 里有原因 |

状态文件里还记 `BOOT_ID`（取自 `/proc/stat` 的 `btime`）。
**设备重启后 `BOOT_ID` 变了，`switch.sh` 会自愈**——把阶段改回
`android-active`，因为上一轮接管已经随重启结束了。

## 3. 进入时序（唯一的一份）

`core/lib/enter.sh` 的 `drm_do_enter()` 是**唯一**的进入时序。
两个前端共用它：

```
安卓侧前端                       容器侧前端
android/enter.sh                 display/desk-takeover.sh
core/switch.sh enter             （desk-takeover 直接调 drm_do_enter）
        │                                 │
        └────────► drm_do_enter() ◄───────┘
```

为什么这很重要：重构前 `drm-takeover.sh` 和 `desk-takeover.sh` 是两份独立实现，
连传给 `kwinwrap` 的环境变量块都不一样（一份用 `KWINWRAP_LEASE`，另一份用
`KWINWRAP_FILTER`），同一台设备上行为不可复现。

`drm_do_enter()` 的步骤：

```
precheck                  环境自检（root / 节点 / 容器）
dev_pre_stop_fixes        设备专属准备（framework 还活着）
android_watchdog_disarm   ★ 解除看门狗，否则 120s 后 system_server 被杀
android_kernel_debug_off  ★ 关 drm.debug，否则帧率崩
android_stop_framework    仅在 FULL_STOP=1 时（默认关，会毁音频）
android_stop_display      停 SF + 点名停 composer
android_wait_composer_release 30
                           ★ 判据 = composer 从 /proc/*/fd 的 card0 持有者里消失
                             **不是** init.svc 状态
ds_start                  启动 Droidspaces 容器（仅安卓侧）
drm_stage_payload_to_container
drm_run_session_up        → linux/session-up.sh
  ├─ drm_kill_linux_stack
  ├─ drm_ensure_drm_nodes / touch node
  ├─ drm_write_udev_records      伪装 E:DRIVER=vmwgfx
  ├─ drm_start_kwin              kwinwrap 交接
  ├─ drm_wayland_selfcheck
  ├─ drm_force_display_on
  ├─ drm_start_desktop           kactivitymanagerd → plasmashell → portal
  ├─ drm_wait_kwin_holds_drm
  ├─ drm_input_settle
  ├─ net_takeover_wifi           尽力而为，绝不 die
  └─ dev_post_session_fixes
verify KWIN_HOLDS_DRM
PHASE=linux-active
```

KWin 拿到面板之后，**任何失败都只警告不回滚** —— 屏幕已经归 Linux 了，
把它交回去需要重启，所以"回滚"比"带着警告继续"更糟。

## 4. kwinwrap：交接桥

`tools/runtime/kwinwrap.c` 是全项目心脏。它做的事：

```
以 root 启动
  ├─ init_split()           ★ 运行时发现 split 几何（原来写死 piano 的常量）
  ├─ open /dev/dri/card0
  ├─ DRM_SET_MASTER
  ├─ 预清理安卓遗留的 atomic 状态
  │    · 释放它占用的 plane / CRTC
  │    · connector DPMS 拉回 On
  │    ★ 不做这步，KWin 的第一次 commit 会撞 -22
  ├─ 钉背光（KWINWRAP_BRIGHTNESS）
  │    ★ 安卓关机流程会写 brightness=0，之后 KWin 从不知道这个属性
  ├─ DROP_MASTER
  │    ★ 让 KWin 自己的第一次 open 按"首个打开者"规则成为 master
  ├─ initgroups + setuid/setgid 降权
  └─ exec kwin_wayland
```

之后 KWin 用 **stock GBM + EGL + atomic commit** 驱动面板，全程普通用户权限。

### 可选模式

| 环境变量 | 作用 |
|---|---|
| `KWINWRAP_HIJACK` | 拿 master（核心功能） |
| `KWINWRAP_FILTER` | 重写 commit，剥掉 KWin 的幻影输出，只留真面板 |
| `KWINWRAP_SECCOMP` | |
| `KWINWRAP_LEASE` | 用 DRM lease 而不是降权（默认关，见下） |
| `KWINWRAP_BRIGHTNESS` | 交接时钉住的亮度 |
| `KWINWRAP_SPLIT_*` | 覆盖 split 几何发现结果 |
| `KWINWRAP_KEEP` | 覆盖 FILTER 保留的对象列表 |

`LEASE` 默认关闭的原因：v6.6 的 `drm_lease_held()` 对非 master 文件返回 true，
所以 KWin 那个 `auth=0` 的 side-file 能看穿 lease，里面的 blob 在 lease relay fd
上找不到。后来用重写 `GetResources` 代替了它。

## 5. 返回安卓：为什么只能重启

这是本项目最重要的一个设计结论，值得单独说。

接管时容器启动会**破坏安卓 ueventd 的 netlink**，所以 **停容器 ≠ 恢复**。
原地恢复后典型症状：

- 卡开机界面约 1 分钟
- 进系统后不定时重启（watchdog 杀 vendor HAL，SELinux 拒绝
  `signal` 到 `u:r:oplus_hal_displaypanelfeature`）
- U 盘 / pogo 键盘等热插拔节点永远建不出来

所以正常路径是**整机重启**。链路：

```
Linux 桌面
  linux/drm-switch.sh  →  touch /root/.drm-exit-request
                          （共享目录：容器 /root ↔ 安卓 /mnt/Droidspaces/<c>/root）
                       →  1 秒后杀 plasmashell / kwin
        ↓
安卓侧
  core/switch.sh watch  →  1 秒轮询 .drm-exit-request
                       →  ★ 先删掉请求文件，再停容器
                            （否则重启后残留的请求会立刻再触发一次）
                       →  ds_stop
                       →  杀 argsloop
                       →  rm -f hal-direct.sock
                       →  sync
                       →  /system/bin/reboot
```

**只有 `/system/bin/reboot` 有效。** `svc power reboot` 和
`setprop sys.powerctl reboot` 都是**静默 no-op** —— 不报错，也不重启。

`display/desk-stop.sh` 保留了原地恢复作为退路，但脚本里写清了代价。

## 6. 网络：尽力而为

接管后 `netd` 被停，安卓那套 per-interface 路由表 + fwmark 没人维护。
兜底方案是加一条独立路由表 + 一条 rule。

**网络接管永不 `die`。** 关联失败、DHCP 失败、出口不通，都只打警告。
理由：屏幕已经归 Linux 了，为了网络把桌面回滚掉是净损失。

### ⛔ 红线

```sh
ip link set <wifi> up     # 永远不要
```

接管后对无线网卡做 `up`：

```
cnss: Failed to start MHI err=-110
Recovery is already in progress → ASSERT 2436
```

→ adbd 死掉 → 黑屏。只能强重启。

### PSK 不进日志

重构前的 `desk-takeover.sh` 开着 `set -x`，把 WiFi PSK **明文**写进了日志。
现在 `net_android_current_psk()` 整个包在 `set +x` 里，且从不回显。

## 7. 目录职责

```
core/lib/       纯逻辑，可被任何脚本 source
  common.sh     日志 / 状态 / 超时 / 锁 / 脱钩 / payload 可信性自检
  device.sh     设备适配加载器（别名表 + 匹配）
  android.sh    安卓侧操作，单出口 android_exec（本地 sh 或 adb）
  container.sh  Droidspaces 容器
  display.sh    DRM 节点 / 触摸节点 / udev / 合成器 / 桌面会话
  net.sh        WiFi 接管
  enter.sh      ★ 唯一的进入时序
  boot.sh       容器侧脚本的统一引导

core/device/    纯数据，一个设备一个文件
core/switch.sh  状态机 CLI（唯一的命令入口）

linux/          跑在容器里（Linux 应用 + 会话拉起）
android/        跑在安卓上（APK + 包装脚本）
display/        两条路径都会用到的显示层脚本
tools/runtime/  脚本硬依赖的最小集
tools/probe/    设备适配期探针
tools/protocol/ wayland 协议桩
```

## 8. 与参考实现的关键差异

参考：[Goldzxcbug/droid-drm-takeover](https://github.com/Goldzxcbug/droid-drm-takeover)

| 方面 | 参考实现 | 本项目 |
|---|---|---|
| 安卓侧应用 | 无（手敲 adb 命令） | APK，程序化 UI，无 Gradle/AndroidX |
| Linux 侧应用 | 无（`.desktop` 从未装进菜单） | `drm-switch`，零依赖，`install.sh` 真的写进菜单 |
| 状态管理 | 一个 `takeover.ok` 空文件，且被无条件 touch（判据失效） | 状态机 + `BOOT_ID` 自愈 |
| 进入时序 | 三个互不知晓的入口，各自实现回滚 | `drm_do_enter()` 唯一一份 |
| 设备常量 | 散落在代码里（`kwinwrap.c` 的 `SPLIT_*`、`setprop.c` 的 conn 67） | `core/device/*.sh` 数据文件，运行时发现兜底 |
| split 几何 | 编译期 `#define`（piano 的值），发现失败静默用错 | 运行时发现 + `--probe-split`，失败**大声告警** |
| 桌面账号 | 写死 `Gold` / `xieyizhou` | 运行时 `getent passwd 1000` |
| 触摸节点 | 写死 `event11` | 按 `DEV_TOUCH_NAME` 反查 |
| 看门狗还原 | 回滚不还原 ⇒ 永久失去看门狗 | `REARM` 成对，`desk-stop.sh` 也调 |
| 核心工具部署 | `kwinwrap` / `bthci-bridge` 不在任何自动部署清单里 | 统一 payload + `make runtime` 子集 |
| PSK 处理 | `set -x` 把明文 PSK 写进日志 | `set +x` 包裹，从不回显 |
| 超时 | 裸 `adb` 调用（实测卡死导致纯黑屏） | 所有外部调用过 `drm_timeout` |
| 路径安全 | payload 在 `shell` 可写的 `/data/local/tmp` 却以 root 执行 | root-only 目录 + 运行前自检 |
| 源码分组 | `src/` 混装核心与探针 | `tools/{runtime,probe,protocol}` |
| CI | 只 `file` 检查 3 个产物 | 全产物架构校验 + `make runtime` 子集校验 + 脚本 POSIX 门禁 + APK 构建 |
| 设备支持 | 1 台 | 4 个适配层（含 `generic` 全发现兜底） |

### 保留的设计

有几件事参考实现做对了，直接沿用：

- **reboot-only 返回** —— 见第 5 节，这是唯一正确的做法
- **Droidspaces 容器** —— 同样的运行时环境
- **`E:DRIVER=vmwgfx` 伪装** —— KWin 白名单的唯一可行解
- **`MESA_LOADER_DRIVER_OVERRIDE=kgsl`** —— KGSL 路径
