## 1. 症状与第一层定位

### 1.1 容器里 ALSA 看不到声卡

```
$ ls -l /dev/snd
total 0
crw-rw----+ 1 root audio 116, 33 Oct 12 15:15 timer        ← 只有这一个

$ cat /proc/asound/cards
 0 [pineapplemtpsnd]: pineapple-mtp-s - pineapple-mtp-snd-card
                      pineapple-mtp-snd-card

$ ls -l /proc/asound
dr-xr-xr-x. 4 root root 0 Oct 12 21:53 card0
-r--r--r--. 1 root root 0 Oct 12 22:42 cards
-r--r--r--. 1 root root 0 Oct 12 22:42 devices
lrwxrwxrwx. 1 root root 5 Oct 12 22:42 pineapplemtpsnd -> card0
```

⇒ **驱动在、`/proc/asound` 在、`/sys/class/sound` 在，缺的只是设备节点。**
（`aplay -l` 此时报 `no soundcards found`。）

### 1.2 为什么缺：devtmpfs 在开机时从未被挂载

| 侧 | `/dev` 的文件系统 | 证据 |
|---|---|---|
| 安卓 | **tmpfs**（ueventd 建节点） | `grep ' /dev ' /proc/self/mountinfo` → `0:19 / /dev ... - tmpfs tmpfs` |
| 容器 | **devtmpfs**（droidspaces 新挂） | 容器 mountinfo → `0:5 / /dev ... - devtmpfs devtmpfs` |

`devtmpfs_create_node()` 的第一句是 `if (!devtmpfs_mount) return 0;`，
而 `devtmpfs_mount` 只在有人 mount devtmpfs 时置位。安卓从不 mount 它
⇒ **开机期间一个节点都没建**。容器后来挂上 devtmpfs 时，里面只有"挂载之后才被创建"的节点
（`/dev/dri`、`/dev/input`、`/dev/binder` 有），而声卡在开机早期就注册完了 ⇒ snd 节点永远补不上。

旁证：droidspaces 二进制的 `/dev` 白名单里没有 `/dev/snd`：

```
$ strings -a /data/local/Droidspaces/bin/droidspaces | grep '^/dev'
/dev
/dev/ashmem
/dev/binder
/dev/dri
/dev/dxg
/dev/fuse
/dev/input      ...（无 /dev/snd）
```

droidspaces 的音频支持是 **Termux 专属**的：

```
--pulse-audio         Configure PulseAudio sound server support
PulseAudio: binary not found at %s. Is pulseaudio installed in Termux?
/data/data/com.termux/files/usr/bin/pulseaudio
AAudio_sink
export PULSE_SERVER='unix:/tmp/.pulse-socket'
```

而本机 **没装 Termux**（`ls /data/data/com.termux` → No such file or directory），
且 `container.config` 里 `enable_pulseaudio=0`，打开它要重启容器（红线）。

### 4.4 这是"容器 + 停 SurfaceFlinger"的必然后果

`core/lib/android.sh` 现在默认**不** stop framework，注释理由是"保护 audioserver"：

```
#    `stop` 会连 audioserver 一起放倒，而 audioserver 一旦没有 activity
#    注册 media.audio_flinger 就永久废掉音频。所以这里**默认不做**，
drm_log "跳过 framework stop（FULL_STOP=1 才执行；保护 audioserver）"
```

但在 DRM 接管下，这个默认恰好制造了 §4.3 的死循环 ——
**audioserver 并没有被"保护"住，它每 79 秒被连坐重启一次。**
两条出路二选一（本次**没有动**，留给用户决定）：

1. **彻底停 framework**（`stop`），走 A 路直连 HAL —— 上游的选择（`ref-upstream/ade/ade.sh` P1）。
2. 不停 SurfaceFlinger（放弃 DRM 接管，改回 anland 帧转发）。

## 6. 排除掉的假设（免得别人重走）

| 假设 | 排除依据 |
|---|---|
| "容器缺 `/dev/snd` 节点" | **部分成立**：节点确实缺（已修），但**修好也不出声** —— 10 个 FE 全 EINVAL |
| "是权限/SELinux 不让容器访问声卡" | 反例：`aplay -l`、`amixer -D hw:0 cget`、`mknod`、PCM `open`+`hw_params` **全部成功**；`avc: denied ... scontext=u:r:droidspacesd:s0 ... permissive=1`（droidspacesd 是 permissive 域）。失败点是 `write()` 的 **EINVAL**，不是 EACCES |


而整张卡 **344 个控件里一个 `rate ch fmt` 都没有**（`tinymix | grep -icE 'rate ch fmt'` → 0），
只有 `CODEC_DMA-LPAIF_RXTX-RX-N Channel Map` 这种。

同时 `/sys/module` 里**没有 agm/gsl 模块**（只有
`aw882xx_dlkm`、`wsa883x_dlkm`、`wsa884x_dlkm`、`lpass_cdc_wsa_macro_dlkm`、
`audio_prm_dlkm`、`audio_pkt_dlkm`、`q6_dlkm`、`snd` 等），
且 `/dev/msm_agm` 不存在 ⇒ **AGM 的后端配置接口在本机没暴露出来**。

`PalTest` 也走不通（它要 usecase 表，本机枚举对不上）：

```
$ PalTest 1 -T 300
Enter OpenAndStartUsecase
unkown uasecase            ← 原样输出，1..8 全部如此
openAndstartusecase failed
```

### 8.3 为什么"tinymix 手动配 + tinyplay"这条路也不行

`/vendor/etc/audio/sku_pineapple/mixer_paths_pineapple_mtp.xml` 里
**`<path name="speaker">` 是空的**：

```xml
<path name="speaker">
</path>
```

也就是说**本机的喇叭路径完全由 AGM/PAL 的 metadata 建，mixer_paths 里没有任何 codec/DMA 控件可点**
（对比老平台 mixer_paths 里那一长串 `RX_*`/`Spkr*` 开关）。
⇒ 用 `tinymix` 拼一条路出来在这台机器上**没有素材**。

### 8.4 结论与建议

* **第 4 条路（agmplay/PalTest 直连）是目前最值得继续挖的方向**，因为它
  **完全不需要 audioserver / AudioFlinger / system_server**，正好绕开第 ③ 层的死循环。
* 卡点很具体：**AGM 后端的 `<intf> rate ch fmt` mixer 控件没有暴露**。
  下一步该查的方向（本次未做）：
  1. `/vendor/lib64/libagmmixer.so` 里 `get_device_media_config` 是从
     `backend_conf.xml` 读的，而 `set_*` 写 mixer —— 说明**内核侧 AGM 驱动没注册控件**；
     查 `snd` 模块的参数（`/sys/module/snd/parameters/*`）和
     `techpack` AGM 是否被 `vendor.audio.*` 属性门控。
  2. `mm-audio-ftm`（工厂测试工具）**无参运行时会阻塞并已经读到了
     `pineapplemtpsnd` 声卡**，它走的是 `pcm_open/pcm_write` + `audio_ftm_toneplay_iocontrol`
     私有 ioctl（不是 AGM metadata），**可能是绕开 AGM 的另一条独立通道**，
     值得优先试（注意它无参会挂住，务必用 `timeout`）。
  3. `resourcemanager_pineapple_mtp.xml` 是 PAL 的 usecase/设备表，
     `PalTest` 的 usecaseId 应该从这张表里取（不是 1..8 这种小整数）。
