# `/etc/environment` 污染：掉帧与键盘拖影的共同根因

> 2026-10-12 定位并修复。这篇记录一个**同时导致两个看起来无关的症状**的根因。

## 一、症状

两个现象，一开始被当成两个独立问题查：

1. **桌面掉帧严重**。拉框选图标、拖窗口、开菜单都卡。CPU 并没有吃满，
   所以不像算力不够。实测 `plasmashell` 采样 **0.76 s CPU / 10 s 墙钟（8%）**，
   系统负载 **2.97**。
2. **屏幕键盘刚弹出时，任务栏附近有一层拖影**，几秒后自己消失。
   KWin 日志里能抓到：
   ```
   QSGContext::initialize: depth buffer support missing, expect rendering errors
   QSGContext::initialize: stencil buffer support missing, expect rendering errors
   ```

## 二、根因

容器里的 `/etc/environment` 被 anland 时代写脏了，里面**同时存在三个互相冲突的
渲染驱动选择**：

```
MESA_LOADER_DRIVER_OVERRIDE=msm      ← 选 msm
GALLIUM_DRIVER=kgsl                  ← ★ 又让 Gallium 层走 kgsl
FD_FORCE_KGSL=1                      ← ★ 再强制 kgsl
```

外加一批指向**已经死掉的** Anland 显示桥的变量：

```
ANLAND=1
ANLAND_SOCKET=/run/display.sock
ANLAND_DRM_DEVICE=/dev/dri/renderD128
ANLAND_SKIP_IMPLICIT_SYNC_WAIT=1
WAYLAND_DISPLAY=wayland-0            ← ★ 见下
XCURSOR_SIZE=48
QT_QPA_PLATFORM=wayland
```

两个独立的危害：

- **`GALLIUM_DRIVER=kgsl`** 把 Mesa 的 Gallium 层指到了那条**连 dma-buf 都分配
  不出来**的路径上（`kgsl_bo_new_dmabuf: Failed to allocate dma-buf` ⇒ 黑屏）。
  进程没有崩，只是**一直在慢路径上跑** —— 这就是掉帧。
- **kgsl 路径选出来的 EGL config 没有 depth/stencil 缓冲** ⇒ Qt Quick 场景图
  渲染出错 ⇒ 键盘首次映射时局部区域保留旧内容 = **拖影**。

`WAYLAND_DISPLAY=wayland-0` 是另一个独立的坑：KWin 的 socket 是
`/run/user/1000/taketest`，**没有 `wayland-` 前缀**；`wayland-0` 是失效残留，
会把客户端指到一个不存在的 socket。

## 三、证据

### 修复前后对比（同一台机器，同一时刻采样）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| `plasmashell` CPU | 0.76 s / 10 s = **8%** | 0.09 s / 10 s = **1%** |
| 系统负载（1 min） | 2.97 | 2.55 |
| maliit 的 `MESA_LOADER_DRIVER_OVERRIDE` | `kgsl` | `msm` |
| `QSGContext` depth/stencil 警告 | 有 | **消失** |

### 判定 maliit 拿的是脏环境

```
$ tr '\0' '\n' < /proc/<maliit-pid>/environ | grep -E 'MESA|GALLIUM|FD_'
MESA_LOADER_DRIVER_OVERRIDE=kgsl     ← ★ 脏的
```

对比 KWin 自己的环境是干净的 `msm`。

## 四、为什么 `env -u` 不够（关键教训）

仓库原本已经有摘除机制：

```sh
_unset_env="-u GALLIUM_DRIVER -u FD_FORCE_KGSL"
_unset_env="$_unset_env -u ANLAND -u ANLAND_SOCKET"
_unset_env="$_unset_env -u ANLAND_DRM_DEVICE -u ANLAND_SKIP_IMPLICIT_SYNC_WAIT"
# 启动时：env -u DISPLAY $_unset_env ...
```

**它只对我们脚本亲自 `exec` 的进程有效。** 而实际出问题的进程不在我们的启动链上：

- **maliit 是 KWin 拉起的**（`kwinrc` 的 `[Wayland] InputMethod=`），
  KWin 从自己的环境 fork 它 —— 中间不经过任何 `env -u`。
- 同理还有 `kded6` 加载的模块、plasmashell 的子进程、托盘小程序……

所以 `env -u` 是**打补丁**，改文件才是**断根**。

**结论：改 `/etc/environment` 本身**，一次修好所有进程，包括我们控制不到的那些。
`env -u` 保留作为双保险。

## 五、修法

`core/lib/display.sh` 新增 `drm_fix_container_env()`，在 `drm_start_desktop()`
的**最开头**调用。顺序很重要：

- 必须在**读取 locale 之前** —— 否则读到的是脏文件里的值；
- 必须在**启动 KWin 之前** —— 因为 KWin 会 fork 出 maliit / kded6 等子进程。

函数行为：

1. 幂等：文件里已经没有 kgsl/anland 污染就直接返回；
2. 备份到 `/etc/environment.bak-anland-<epoch>`；
3. 从原文件**抢救**白名单内的变量（上游只放行
   `LANG=*` / `LC_*=*` / `XCURSOR_SIZE=*` / `QT_QPA_PLATFORMTHEME=*`）；
4. 重写文件，只留白名单 + `QT_QPA_PLATFORM=wayland`；
5. 复查污染是否真的消失，写状态位 `ENV_CLEAN`。

## 六、顺带发现的第二个坑：maliit 语言不走环境变量

排查拖影时发现 maliit 键盘只有英文，于是试：

```sh
LANG=zh_CN.UTF-8 LC_ALL=zh_CN.UTF-8 LANGUAGE=zh_CN maliit-keyboard
```

**无效**，日志依然是：

```
wordengine.cpp plugin ".../languages/en/libenplugin.so" loaded
inputmethod_p.h registerActiveLanguage(): activeLanguage is: "en"
DB path: .../languages/en/database_en.db
```

它**完全不读** `LANG` / `LC_ALL` / `LANGUAGE`。真正的存放处是 GSettings
（schema 在 `/usr/share/glib-2.0/schemas/org.maliit.keyboard.maliit.gschema.xml`）：

| 键 | 类型 | 默认 |
|---|---|---|
| `active-language` | `s` | `'en'` |
| `enabled-languages` | `as` | `['en']` |

**第二个坑套在第一个坑里**：这个 schema 的**缓存没编译**时，
`gsettings list-schemas` 根本看不见它（实测输出为空）⇒ gsettings 报 not found
⇒ maliit 只能退回默认 `en`。

所以三步缺一不可：

```sh
glib-compile-schemas /usr/share/glib-2.0/schemas
gsettings set org.maliit.keyboard.maliit enabled-languages "['en', 'zh-hans']"
gsettings set org.maliit.keyboard.maliit active-language 'zh-hans'
```

`gsettings` / `glib-compile-schemas` 都在 **`libglib2.0-bin`** 里 —— 这是屏幕键盘
中文的**硬依赖**，已加进 `NT_DEPS_GLIB`。

中文插件本身是装好的，`maliit-keyboard` 包自带 `zh-hans` + libpinyin 词库。
设好后它打开的会是：

```
/proc/<pid>/fd/12 -> /usr/lib/aarch64-linux-gnu/libpinyin/data/bigram.db
```

## 七、遗留

**键盘拖影没有完全消失。** 修掉 kgsl 后 depth/stencil 警告不见了，但用户仍报告
「任务栏那有一层拖影，只有刚弹出的时候那几秒会有，之后消失」。

这个特征指向**另一个独立问题：首帧 damage 不全**。maliit 首次映射时上报的
damage 只覆盖部分表面，KWin 只重绘那部分，区域外保留旧内容；几秒后（时钟跳动等）
触发一次重绘就自己好了。下一步验证方向：

- `QSG_RENDER_LOOP=basic`（强制全量重绘，绕开线程化渲染循环的部分更新）
- KWin 侧的 damage 追踪开关
- maliit 窗口的不透明性

## 八、教训

1. **"配置明明对却不好使"要往上一层看**：DNS 配置对但解析不了，根因在路由；
   `LANG` 设对但键盘是英文，根因在 GSettings。
2. **环境变量的注入路径要查全**：`/etc/environment` 由 PAM/login 应用，
   **优先级高于父进程传递**。所以父进程干净不代表子进程干净。
3. **`env -u` 只能治我们亲自启动的进程**。要覆盖 KWin 的子进程，必须改文件。
4. **同一份脏配置可以同时造成"性能问题"和"渲染错误"两种表象**，
   别因为它们看起来无关就分开查。
